    • Status ≠ OFD (Non-OFD) → wait 72 hours.
  3. Post-APD Breach: follow BAU SOP — raise delayed delivery task via AA article.

Delivery Full missing

When is it Full/Complete Product Missing?

  • Product(s) received belong to the placed order but entire Item/Style ID is missing.
  • Primary product missing, customer received only accessories (e.g. dress missing but belt received; only shoelace; only charger).

SOP Steps

  1. Check: customer contacted CC within 7 days of delivery date.
  2. Yes → follow task creation SOP. No → decline claim; use verbiage #001 in Missing Component Verbiages; create incident Return/Exchange###Pickup/Exchange serviceability/policy###Return/Exchange serviceability/policy, SA Level Item, Resolved, Queue unchanged.

Task creation (Full Item Missing)

  • Incident: Delivery###Where is my Order?###Missing component, Task Selector Logic: Full, SA Level: Item, Status: Pending, Queue unchanged. Share task TAT.
  • Mandatory probing: Packet condition? (tampered/damaged; if tampered → delivered open / re-sealed with cello tape / adhesive).

Partial item missing

Ask if delivered item has been used.

Garbage item / garbage product cases

  • Garbage items (polybags, papers, cotton, waste) instead of product → treat as Full Missing Product case, follow Missing Component SOP, update Cx VOC clearly (e.g. "Customer claims papers were delivered, complete product missing").
  • Incorrect & usable/garbage product (torn towel, unusable cloth) → Wrong Product Received SOP.
Advise customer not to create Return/Exchange while complaint is worked upon; reassure about return/exchange window. If already created, advise to cancel.

Delivery IMD

  1. Check 1: Probe if no delivery parcel received. If not received → Check 2. If received → Missing Component SOP (item level).
  2. Check 2 — Mode of payment:
    • Complete COD → inform place fresh order; we take feedback on SDA. Incident: Other###I have feedback for you###Courier partner, SA Level Packet. (Coupons one-time use, can't re-provide.) If cx paid SDA via UPI for complete COD (wasn't available, asked SDA to drop packet) → Check 3.
    • Partial COD / Online / MC / LP → Check 3.
  3. Check 3: Contacted within 5 days from Delivered date (delivered date = 0th day)?
    • No → politely decline, educate on 5-day policy (Terms of Use disclaimer), inform who accepted per shipment drop-off status; ask to check with them. After 5 days create incident Delivery###Where is my Order?###POD shared (Packet).
    • Yes → Check 4.
  4. Check 4: Check "Shipment drop-off status" on packet level (Delivered to customer/neighbour/domestic help/security/family/reception/friend/others) for ML/FKL/EK.   5. Check 5: OTP (Code) verification at delivery?
    • ML: no OTP → non-OTP path.
    • 3PL/FKL/EK_E2E: if remarks mention 'Code Verified Delivery' → OTP path; if OTP field blank → non-OTP path.

    OTP verified path:

    • Scenario 1: OTP verified on SA + SDA did NOT ask but cx shared proactively → guide not to share OTP until handed at doorstep; politely decline; create incident Delivery###Where is my Order?###POD shared.

    Non-OTP path: Raise task & share TAT.
