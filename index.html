When customer is anxious about delivery status

  • Reassure the customer; share the promised delivery date and current status.
  • If order is not OFD on APD day → follow "Delay" SOP (below).
  • If customer chooses to check with others and gets back later → tag under Delivery >> Where is my Order? >> Customer Awareness | Anxiety (SA Level: Packet).
  • When customer comes back stating order still not received → proceed to IMD checks.

Delivery Delay

Article: AA_Delayed Delivery (Article 01)

Published 21/8/2026. Covers L1, L1.5, SM. Live with Delayed Delivery Elixir flow for selected pincodes — if an Elixir ticket is created, follow Elixir SOP. If exchange is on hold, follow on-hold SOP (don't raise delayed delivery task). If exchange approved and promised date crossed → raise delayed delivery task.

Order not OFD on APD day

  1. Before 8:00 PM (APD day): Inform customer to wait till EOD. If asked what EOD means → delivery by 9:00 PM.
  2. After 8:00 PM (APD day):
    • Status = OFD → wait 24 hours.
    • Status ≠ OFD (Non-OFD) → wait 72 hours.
  3. Post-APD Breach: follow BAU SOP — raise delayed delivery task via AA article.

Customer wants to collect order from DC/WH

Inform that per policy we deliver to doorstep. Politely decline; we try to deliver on or before the delivery date.

Mandatory checks when task already exists

  • Check if any Task raised on packet ID. There may be a 'Delayed delivery' Task but cx contacted for 'Disputing delivery' or vice versa — ultimate objective is delivery. If such task exists, follow up on same task, mention new VOC in Task & Incident Notes. No additional task.

Without OFD (APD breached)

  1. Task available? YES → Task Followup SOP. NO → Apologize, raise relevant task, update notes, share task TAT. Use Agent Assist screen. Issue Type: Delivery###Where is my Order?###Delayed Delivery, SA Level: Packet ID.

With OFD (APD breached)

  1. Task available? YES → Task Followup SOP. NO → Apologize, raise task, update notes, share TAT. Inform cx to wait until EoD as shipment is OFD.
BFF Gift Orders: Do not promise priority/expedited delivery. Follow BAU SOP, raise task with designated TAT, and fill mandatory Gift Order - Delayed Delivery Form.

Exchange on hold note

If exchange is put on hold (irrespective of SDA visited or incorrectly) → raise respective on-hold task. If exchange approved and promised date crossed → raise delayed delivery task.

Delivery Full missing

When is it Full/Complete Product Missing?

  • Product(s) received belong to the placed order but entire Item/Style ID is missing.
  • Primary product missing, customer received only accessories (e.g. dress missing but belt received; only shoelace; only charger).

SOP Steps

  1. Check: customer contacted CC within 7 days of delivery date.
  2. Yes → follow task creation SOP. No → decline claim; use verbiage #001 in Missing Component Verbiages; create incident Return/Exchange###Pickup/Exchange serviceability/policy###Return/Exchange serviceability/policy, SA Level Item, Resolved, Queue unchanged.

Task creation (Full Item Missing)

  • Incident: Delivery###Where is my Order?###Missing component, Task Selector Logic: Full, SA Level: Item, Status: Pending, Queue unchanged. Share task TAT.
  • Mandatory probing: Packet condition? (tampered/damaged; if tampered → delivered open / re-sealed with cello tape / adhesive).

Partial item missing

Ask if delivered item has been used.

Garbage item / garbage product cases

  • Garbage items (polybags, papers, cotton, waste) instead of product → treat as Full Missing Product case, follow Missing Component SOP, update Cx VOC clearly (e.g. "Customer claims papers were delivered, complete product missing").
  • Incorrect & usable/garbage product (torn towel, unusable cloth) → Wrong Product Received SOP.
Advise customer not to create Return/Exchange while complaint is worked upon; reassure about return/exchange window. If already created, advise to cancel.

Delivery Disputing delivery

Scenario: customer disputes delivery (IMD flow entry)

When customer claims order not delivered but marked delivered, follow the IMD (Incorrectly Marked Delivered) checks. See IMD topic for full check sequence (payment mode, 5-day policy, shipment drop-off status, OTP verification).

Incident for POD shared

  • Issue Type: Delivery###Where is my Order?###POD shared, SA Level: Packet.
  • Ask cx to share screenshot of UPI txn; validate; create IMD Task & share TAT. If unable to share in real time, ask via template; CC reverts within 24 hrs.
  • If cx comes back stating received → update & close incident (Customer Awareness | Anxiety). If still not received → proceed to Check 5 (OTP).

Delivery IMD

Incorrectly Marked Delivered — Check sequence

  1. Check 1: Probe if no delivery parcel received. If not received → Check 2. If received → Missing Component SOP (item level).
  2. Check 2 — Mode of payment:
    • Complete COD → inform place fresh order; we take feedback on SDA. Incident: Other###I have feedback for you###Courier partner, SA Level Packet. (Coupons one-time use, can't re-provide.) If cx paid SDA via UPI for complete COD (wasn't available, asked SDA to drop packet) → Check 3.
    • Partial COD / Online / MC / LP → Check 3.
  3. Check 3: Contacted within 5 days from Delivered date (delivered date = 0th day)?
    • No → politely decline, educate on 5-day policy (Terms of Use disclaimer), inform who accepted per shipment drop-off status; ask to check with them. After 5 days create incident Delivery###Where is my Order?###POD shared (Packet).
    • Yes → Check 4.
  4. Check 4: Check "Shipment drop-off status" on packet level (Delivered to customer/neighbour/domestic help/security/family/reception/friend/others) for ML/FKL/EK. Inform cx accordingly; ask to check with respective person/place. If cx comes back not received → Check 5. (For other logistics skip to Check 5.)
  5. Check 5: OTP (Code) verification at delivery?
    • ML: no OTP → non-OTP path.
    • 3PL/FKL/EK_E2E: if remarks mention 'Code Verified Delivery' → OTP path; if OTP field blank → non-OTP path.

    OTP verified path:

    • Scenario 1: OTP verified on SA + SDA did NOT ask but cx shared proactively → guide not to share OTP until handed at doorstep; politely decline; create incident Delivery###Where is my Order?###POD shared.
    • Scenario 2: OTP verified + SDA asked proactively + cx shared → mandatorily probe reason SDA asked, update notes; raise task & share TAT; guide not to share OTP.

    Non-OTP path: Raise task & share TAT.

Task creation

  • Online/Partial COD → create IMD Task & share TAT.
  • Complete COD (cx paid via UPI) → validate screenshot (UPI amount, amount mentioned, complete COD order) then create IMD Task & close incident where cx shared screenshot.

Two imp probing questions

1. Shipment drop off status · 2. OTP

Delivery Order Status

AA_Order Status Update - Packed to Delivered

For queries on order status moving from Packed to Delivered, reassure based on current status; if stuck, raise appropriate task.

Re-dial feature (general process)

Enabled across L1-Inbound/Call, L1.5 & High Care. Auto redial on call drop (limited to 1 attempt). Scenarios: call drops before understanding issue → select 'Call Disconnected while Talking' in Ubona; if cx answers address concerns, else dispose as unanswered/call-drop. If call drops after understanding but info not shared → redial & share. Redial not required if drops during closing/iSAT after all actions complete.

Always update REDIAL Attempt Notes in incident with reason & summary when major actions already completed before drop.

Return AA_Time taken for pickup

Pick up promise is today / not crossed + Return is OFP + no status update post OFP

  1. Has OFP entry crossed 1 day?
    • No: cx before 8 PM → wait until 8 PM. cx after 8 PM → wait 24 hours, reach out if still unsuccessful. Incident: Return/Exchange - Where is my pickup? - Time taken for Pickup, SA Level: Return.
    • Yes (crossed 1 day, post 24h, still no update): raise task & share TAT. Incident: Return/Exchange###I do not agree with your Pick up attempt###No Pick Up Attempt, Queue: Outbound, Status: Pending, SA Level: Return.

Pickup not OTP-verified

  • Create new RID (if no active RID exists) and raise Disputing Pickup Task via Agent Assist; share TAT. Warm transfer to L1.5/TL if cx insists and doesn't agree to TAT.
  • NDR communication if reasons: Customer refused / not reachable / out of delivery area / incorrect contact number. NDR script: within 24 hours of pickup remarks update, cx receives call/SMS/email to confirm reattempt.

Return Disputing pickup

First determine: myntra attribute or customer attribute?

  • Customer attribute: ask cx to wait for next attempt; tag under AA_Time taken for pickup - Global (All LOBs).
  • Myntra attribute: raise task & share task TAT. Inform cx we will try reattempt within next 24 hours (do not assure same); follow up until task TAT.

NDR processes

Action: raise task & share TAT. Capture Old return ID, creation date of old RID and new RID in task/INC notes (if previous RIDs). For L1 (IB/Chat): warm transfer to L1.5/TL if cx doesn't agree to TAT and insists.

Scenarios: customer claims item picked but SA shows failed / OFP / on hold

  • Claimed picked but SA pick up failed → raise task & share TAT. Incident: Refund###Picked up - refund pending###Picked up QC pending/Status not updated.
  • Claimed picked but SA status OFP, no further updates: if 24h (or 48h for 3PL) crossed → raise task; else wait 24h/48h then educate on QC TAT. Incident: Refund###Return - refund pending###Time Taken for Refund.
  • RID on hold & not picked as per SA → raise task & share TAT. Incident: Refund###Picked up - refund pending###Picked up QC pending/Status not updated.

Scenario: customer claims picked but RID declined on SA

Incident: Refund###Picked Up-Refund Pending###Picked up return id declined, SA Level: Return, Selector Logistics: Parent_All Logistics, Queue: Outbound, Status: Pending. Share task TAT.

Refund Refund Simplified

Success (refund processed)

  • Within TAT: Case A ARN not available → share Refund TAT, update notes. Incident Refund###Return - refund pending###Refunded-TAT Provided (Agent Assist). Case B ARN available → share Refund TAT & ARN. Incident Refund###Return - refund pending###Refunded-Shared Bank ref# (SMART Assist).
  • Outside TAT: if ARN available share TAT & ARN; else raise task Refund###Return -refund pending###Refunded- ARN Number required, SA Level Return.

Pending

  • Within TAT (104 hrs from transaction time) → inform validating refund with payment partners; wait 104 hrs. Incident Refund###Return - refund pending###Refunded-TAT Provided.
  • Outside 104 hrs → check if auto task raised; if yes follow AA_Refund Tasks follow-up SOP; if no raise Refund###Return - refund pending###Auto task - Creation Failed, task selector logic as per refund instrument, SA Level Return.
  • Within 24h of refund transaction date in PPS log → auto task should be raised for Tx_Failure/TX_Not_Attempted/No PPS log; create incident Refund###Return - refund pending###Time Taken for Refund, SA Level Return.
  • Outside 24h → if auto PPS refund task raised follow up; else create Refund###Return - refund pending###Auto task - Creation Failed, refund instrument as per payment mode, SA Level Return.

Failure

  • Within TAT 24 hrs → Incident Refund###Return - refund pending###Time Taken for Refund, SA Level Return.
  • Outside TAT auto task creation failed → Incident Refund###Return - refund pending###Auto task - Creation Failed, refund instrument as per payment mode, SA Level Return.

ARN Dispute Handling

Apologize; probe if same account debited; check transaction range sale date to current; check if bank support team contacted (not bank/branch); if bank support unable to locate refund with ref number → request cx to dispute transaction with bank support as 'Refund Not Processed'. Bank support team printed on flip side of card. Incident Refund###Return - refund pending###Disputing-Refund/Bank ref#/UTR, SA Level Return. If still disputes → ask TL/TC to reopen ARN task incident, move to ED pending.

Refund Pre Processed

Declined Orders | D=Success & V=Failure etc.

Go to order level and check payment details first. Check payment instrument, transaction type & status. AA_Declined Orders variants: D=Success&V=Failure; D=Success/V=Not Executed; D=3DS-Redirect; D/V=Fail/Fail or Success/Pending or no-clarity; D=Fail&V=Void Not executed; D/V=Success.

Within 48 hours or post 48 hours?

  • Within 48 hrs: Incident Refund###Order not processed/Multiple Debits/POS###Order-Declined- Payment not received, SA Level: Order. Inform cx order will be declined within 48 hours; can place fresh order.
  • Outside 48 hrs: Incident Refund###Return - refund pending###Auto task - Creation Failed, SA Level: Item, task selector logic as per refund instrument. Share TAT; ask to place fresh order.
Preprocessed orders will not be successful and declined within 48 hours. If exchange order preprocessed, ask cx to place fresh order. Once declined follow declined order process.

Refund Declined orders

See Pre Processed. Declined order refund flows: within TAT share TAT; outside TAT refer AA_OR [PPS_Success] articles. If ARN available share TAT & ARN; if not raise Refund###Return -refund pending###Refunded- ARN Number required.

Refund Success Return within

Refund successful within TAT. Case A ARN not available → share Refund TAT. Case B ARN available → share Refund TAT & ARN number. Incident as per above.

Refund OR Return Outside

Refund outside TAT (OR Return Outside). Refer AA_OR [PPS_Success] <CC/DC/UPI> RID - outside TAT (L1/L1.5/Highcare) (Check at Return Level). If ARN available share TAT & ARN; else raise task Refund###Return -refund pending###Refunded- ARN Number required.

Refund OR Return Pending

Pending refund for OR return. Check if contacted within 104 hours from Transaction Time (Return level → Refund Details → Issue Refund to calculate Transaction Time). Within 104h → validate with partners, wait. Outside → raise auto task creation failed if not already raised.

Refund Ret pending outside

Return refund pending outside TAT. Follow failure/pending flow; raise appropriate task & share TAT.

Refund Ret refund fail

Refund failed. Within TAT 24h → Incident Time Taken for Refund. Outside TAT → auto task creation failed with refund instrument as per payment mode.

Refund Refund- Search void

Search void refund cases handled via refund simplified flow; check payment logs and PPS status, document transaction status in notes (TX_pending/No PPS).

Refund AA_ARN Dispute (Return

See Refund Simplified → ARN Dispute Handling. If cx still disputes, ask TL/TC to reopen ARN task incident and move to ED pending. L1 can inform cx of callback within 24-48 hours.

Refund ROH

Wrong Product Received (ROH / exchange on hold)

  • If cx created exchange with incorrect reason but not on hold yet (processing/packed/shipped) and product in stock & pincode serviceable → ask cx to cancel exchange and create new one with valid WPR reason. Incident: Return/Exchange###How do I return/exchange this item?###Incorrect Reason selected while Return creation.
  • If exchange on hold for WPR / approved exchange put on hold at doorstep → raise task & share TAT. Incident: Return/Exchange###Why is my Exchange rejected/put on hold?###Wrong Product Received, SA Level: Item (Parent Order).
  • If cx facing issues creating exchange (app issue, no coupon, out of stock, non-serviceable, non-returnable, window breached, invoice interchange) → ask cx to share images (JPG), then create return with reason "Different product was delivered, DPWD, 9" / subreason "Different product was delivered, DPD, 7"; auto task generated; share TAT. Incident: Return/Exchange###Pickup/Exchange serviceability/policy###ROH Cases - Probed for more information.

Within/Outside return window

  • Within window → redirect cx to create return in My-Order; guide steps. If created on call and task generated → share exact TAT. Incident: Return/Exchange###How do I return/exchange this item?###Incorrect Reason selected while Return creation.
  • Outside window → request images; after receiving create return with above reasons & auto task; share 24h. If no images → request images, provide 48h acknowledgement TAT.
  • Outside exception window → politely decline. Incident: Return/Exchange###Pickup/Exchange Serviceability/Policy###Return/Exchange Serviceability/Policy.

Cx unable to create return (non-returnable / no coupon / window breached / technical)

Request images; after receiving create return with DPWD/DPD reasons; auto task; share TAT. Incident: Return/Exchange###Pickup/Exchange serviceability/policy###ROH Cases - Probed for more information.

Invoice interchange case → follow WPR SOP.

Refund WPR Exchange

Wrong Product Received exchange flow: guide cx to create exchange proactively selecting WPR reason (Primary: Different product (Not what I ordered); Secondary: Received a completely different product; upload images). If on hold follow exchange on-hold SOP. If not on hold yet but wrong reason → cancel & recreate with valid reason if in stock & serviceable.

Refund WPR Return

Wrong Product Received return: guide cx to create return (Primary: Different product (Not what I ordered); Secondary: Received a completely different product). If cx unable, collect images and create return with DPWD/DPD reasons; auto task generated; share TAT.

Refund Order Cancellation

Cx calling first time for cancellation

Fill the form. Check order status:

  • Packed/Processing: fill form, share 24h TAT. Incident Cancel###I want to cancel my order###Order cancellation Request, SA Level Item/Packet.
  • Shipped: raise task, share 24h TAT (do not share task TAT). Incident Cancel###I want to cancel my order###Customer Refused - Order not cancelled, SA Level Packet.
  • Packed but item-level cancellation reason updated: Scenario A (cx initiated cancellation now wants order) → cannot reverse; place fresh order; fill form share 24h. Scenario B (still not cancelled) → fill form share 24h. Incident Cancel###I want to cancel my order###Order cancellation Request, SA Level Packet.

Incident found (already exists)
